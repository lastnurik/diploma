# Pre Defense Task Plan for 24 October 2026

This plan turns the diploma proposal and pre-defense checklist into assignable YouTrack work. The project is **Development of an AI-Assisted Platform for Generating Playable Browser Games from User-Provided Storylines**. Its intended result is a playable 2D browser game with a beginning, meaningful actions, and an ending, generated from a user's story. The plan covers the **first pre-defense**, not the complete May 2027 implementation. All times and dates below use Kazakhstan time.

**Owners:** Almadi Madiuly (M, frontend and UX/UI), Zhaksylyk Aldiyar (A, backend and platform architecture), Yessengeldi Nurgeldi (N, AI generation). The three share non-development research and writing. Each task has one accountable owner; the listed reviewer checks it without becoming a second owner. Create the tasks in YouTrack with the actual issue IDs, priority, assignee, due date, dependencies, expected outcome and acceptance criteria. The temporary IDs below are for planning only.

**Working rule:** Each owner commits their own work from their own account on a branch named with the YouTrack ID; a different member reviews the pull request before merging. A completed task has its named artifact in the repository, a working link in YouTrack, and the stated checks met. Drafts and uncollected evidence must not be marked complete.

## Validation result and unresolved decisions

The 36 tasks each have one owner, a bounded artifact, a checkable finish condition and a day; non-development work is distributed across all three. Shared decisions are confined to the early specification and final reconciliation, leaving research, comparisons, requirements and diagrams open to parallel work. The tasks cover every numbered pre-defense component, every repository step and the stated minimum repository contents. The two largest risks for the 24 October deadline are obtaining qualifying user discussions/client agreement and receiving substantive supervisor feedback in time. Treat both as open until they actually happen.

Before work starts, settle: **(1)** whether the GitHub repository will be public or private, **(2)** where the survey can reach likely authors/teachers/small teams and whether brief follow-up discussions are feasible, **(3)** when the supervisor can review drafts (currently unknown), and **(4)** whether the committee expects a runnable slice on 24 October or accepts the specified mockup/prototype materials. The written minimum says a complete application is not required.
